## Component Selection Rationale

### 1. Frontend Framework: Next.js (App Router)
* **Server Components & SSR:** Essential for instant initial page loads and search engine crawler indexing. Public baker pages are rendered on the server with minimal client-side hydration.
* **Dynamic Route Matching:** Supports city and category discovery pages alongside multi-tenant storefronts (`/:storeSlug`).
* **Image Optimization:** Automated responsive image resizing and WebP conversion via `next/image`.

### 2. Hosting & Deployment: Vercel
* **Global Edge Network:** Low-latency caching of static assets across Indian nodes (Mumbai, Chennai, Delhi).
* **Zero-Downtime Deployments:** Atomic deploys with instant rollbacks and preview URLs for continuous integration.

### 3. Database & ORM: PostgreSQL + Prisma
* **PostgreSQL:** Industry-standard ACID compliance for store profiles, catalog pricing, variants, and future transactional accounting.
* **Geospatial Support:** Capable of running spatial queries (Haversine distance or PostGIS) for location-based bakery search.
* **Prisma ORM:** End-to-end TypeScript type-safety from database schema to API response handlers, eliminating runtime schema mismatches.

### 4. Authentication: Better Auth
* **Database-backed identity:** Better Auth uses the Prisma/PostgreSQL data model for users, accounts, sessions, and verification records.
* **Sign-in and recovery:** Email/password, email OTP verification, password recovery, and supported social providers are managed through the application auth layer.

### 5. Media & Asset Storage: Cloudflare R2
* **Zero Egress Fees:** Bakery storefronts are media-heavy (cake galleries, menu pictures). Cloudflare R2 provides S3 API compatibility with zero egress bandwidth charges.
* **Fast Global CDN:** High-speed asset caching through Cloudflare's global edge network.
